# 05 调试与排障清单

本章按“现场最常见问题”整理。  
真正上机后，最重要的能力不是背 API，而是能快速判断问题在：

- 接线
- 供电
- 驱动器参数
- 运动控制卡配置
- 总线状态
- 软件状态机
- 业务联锁

## 1. 上机前检查

每次第一次上电或改线后，都先做这张检查表：

| 项目 | 检查内容 |
| --- | --- |
| 电源 | 控制电源、驱动电源、24V I/O 电源是否正常 |
| 急停 | 急停回路是否闭合，释放后是否真实恢复 |
| STO | 驱动器 STO 是否释放，安全继电器是否导通 |
| 限位 | 正负限位接线方向是否正确，NO/NC 类型与触发逻辑是否符合配置 |
| 原点 | 原点开关位置是否合理，触发电平是否正确 |
| 编码器 | 编码器反馈是否有值，方向是否正确 |
| 驱动器 | 参数、控制模式、报警状态是否确认 |
| 运动控制卡 | 驱动、固件、设备识别是否正常 |
| 总线 | EtherCAT 拓扑、从站顺序、网线和屏蔽是否正常 |
| 机械 | 运动范围内是否有干涉、卡滞、未锁紧部件 |

## 2. 最小调试顺序

不要一上来就点自动运行。推荐按下面顺序做：

1. 只读状态，不下运动命令
2. 报警复位
3. 使能
4. 点动
5. 停止
6. 回零
7. 绝对定位
8. 相对定位
9. 双轴联动
10. 自动流程

## 3. 常见故障速查表

### 故障 1：软件显示在线，但轴完全不动

可能原因：

- 伺服未使能
- STO 未释放
- 驱动器还在报警
- 运动模式不对
- 目标位置已下发，但被联锁拦住

优先检查：

1. `Servo ON` 是否真的到驱动器
2. 驱动器面板是否有报警码
3. 限位、急停、门禁、气压等前置条件
4. EtherCAT 驱动器的 `Controlword/Statusword`

### 故障 2：能使能，但一运动立刻报警

可能原因：

- 电机线序或编码器方向不对
- 增益过高
- 加速度过大
- 软限位或硬限位设置错误
- 机械卡死

优先检查：

- 手动低速点动是否正常
- 实际位置变化方向是否与命令一致
- 跟随误差是否快速放大

### 故障 3：回零方向反了，或一直找不到原点

可能原因：

- 原点方向参数设置错误
- 原点开关接线逻辑取反
- 先碰到限位了
- 回零模式与机构实际不匹配

优先检查：

- 原点输入在 I/O 监控里是否会变化
- 回零顺序是“找 ORG”还是“找 ORG + Z 相”
- 回零速度是否过快导致冲过开关

### 故障 4：位置会飘，重复定位不稳定

可能原因：

- 机械背隙大
- 联轴器松动
- 编码器反馈异常
- 电机抱闸释放不稳定
- 伺服增益或滤波参数不合适

优先检查：

- 机械连接是否可靠
- 电机停止后实际位置是否仍抖动
- 是否存在外力拖拽或负载变化

### 故障 5：双轴插补轨迹不圆、不直、拐角有顿挫

可能原因：

- 两轴单位换算不一致
- 加减速参数不协调
- 轨迹缓存不足
- 总线同步抖动
- 机械刚性差

优先检查：

- `PPU` 或工程单位换算
- 两轴实际速度与命令速度是否一致
- EtherCAT 周期和 jitter

### 故障 6：EtherCAT 从站在线，但上不了 OP

可能原因：

- PDO 映射不匹配
- ESI 文件或驱动器描述不一致
- 某从站供电异常
- 拓扑顺序与配置不一致

优先检查：

- 主站诊断信息
- 从站状态机停在哪个状态
- 配置下载是否成功

### 故障 7：上 OP 了，但 CiA 402 轴还是不动

可能原因：

- Operation Mode 错
- Controlword 顺序不对
- 目标位置没有更新
- 位置命令单位不对

优先检查：

- 当前模式是否为 `CSP`、`PP` 或你预期模式
- 状态字是否进入 `Operation Enabled`
- 目标位置与实际位置变化趋势

### 故障 8：比较输出或飞拍丢触发

可能原因：

- 用了软件触发而不是硬件触发
- 比较位置设置过密
- 运动速度过高
- 触发输出脉宽过窄

优先检查：

- 是否使用控制卡硬件比较功能
- 外设是否真的能接收到脉冲
- 触发时刻和编码器位置是否匹配

### 故障 9：恢复急停后，软件显示正常但轴仍不能动

可能原因：

- 安全继电器未复位
- STO 仍然有效
- 使能链没有重新打通
- 软件状态机还停留在 Fault

优先检查：

- 急停复位流程是否包含“清报警 -> 清联锁 -> 重新使能”
- 是否需要人工确认再恢复 Ready

### 故障 10：程序偶发卡顿，运动状态刷新不稳定

可能原因：

- UI 线程阻塞
- 日志同步写盘
- 视觉或网络任务抢占资源
- 总线线程和业务线程混在一起

优先检查：

- 线程模型
- CPU 占用
- 网卡驱动和电源管理
- 是否有大文件写盘、杀毒扫描、Windows 更新影响

### 故障 11：上电后正极限或负极限一直亮

可能原因：

- 限位开关接线逻辑与软件配置相反
- 常闭型开关断线
- I/O 点号映射错误
- 驱动器侧和主站侧对同一信号做了重复取反

优先检查：

- 现场限位输入是 `NO` 还是 `NC`
- HMI 上的限位状态是否与 I/O 监控页一致
- 手动压下和释放限位开关时，PDO 与输入点是否同步变化

### 故障 12：热复位后仍然异常，不确定是否该冷复位

可能原因：

- 只是软件状态清掉了，但驱动器故障并未真正释放
- EtherCAT 从站内部状态残留
- 安全链恢复了，但驱动器需要重新上电才允许再使能

优先检查：

- 驱动器面板报警码是否还在
- 从站是否能稳定进入 `OP`
- 热复位后 `Controlword/Statusword` 是否真的回到初始使能流程

建议判断：

- 还能稳定在线、报警码可清、I/O 状态一致时，先用热复位
- 驱动器锁死、从站不上 OP、状态反复不一致时，直接进入冷复位流程

### 故障 13：轴会抖动、啸叫，低速都不稳

可能原因：

- 伺服增益偏高
- 加速度或减速度设置过猛
- 机械刚性不足
- 电机方向、编码器方向或电子齿轮比设置不一致
- 停止后仍被外力或机构卡滞影响

优先检查：

- 先把速度和加减速降到保守值，再看现象是否明显缓解
- 实际位置反馈是否平稳，是否存在明显来回摆动
- 编码器方向和命令方向是否一致
- 联轴器、丝杆座、皮带张力、抱闸释放是否正常

### 故障 14：脉冲轴疑似丢步，或伺服跟随误差过大

可能原因：

- 单位换算错误，命令量和实际运动量不一致
- 脉冲频率、速度、加速度超出机构或驱动能力
- 机械卡滞、负载过重、背隙过大
- 编码器反馈异常
- 伺服参数不合适，导致跟随误差快速放大

优先检查：

- `pulse/mm`、编码器分辨率、电子齿轮比是否一致
- 指令位置与实际位置差值是在持续累计，还是只在加减速阶段放大
- 低速运行是否正常，高速才异常，还是全程异常
- 机械端是否存在明显阻力、碰擦或松动

### 故障 15：报警无法清除，或者一复位马上再报

可能原因：

- 报警根因没有消失
- 急停、STO、门禁、安全继电器仍未恢复
- 驱动器要求特定复位顺序或重新上电
- 软件只清了界面状态，没有真正把复位命令下到驱动器
- EtherCAT 从站虽然在线，但模式、PDO 或状态机仍不一致

优先检查：

- 驱动器面板报警码和软件报警码是否一致
- 复位动作后，`Alarm` 位、`Statusword`、I/O 联锁状态是否真实变化
- 是否需要先清硬件条件，再做报警复位，再重新使能
- 热复位无效时，是否已经满足冷复位条件

## 4. 从哪些证据定位问题最快

现场排障最忌讳“靠感觉改参数”。  
建议固定按下面几类证据交叉判断：

| 证据 | 要看什么 | 常见价值 |
| --- | --- | --- |
| 电气图 | 使能、报警、限位、原点、急停、STO 回路 | 判断接线方向、联锁路径和是否断线 |
| I/O 状态 | 按下或触发现场元件时，输入位是否真实变化 | 判断传感器、电平极性、点号映射 |
| 报警码 | 驱动器面板、HMI、日志中的报警编码与说明 | 快速缩小到电机、驱动器、反馈或安全链问题 |
| 参数配置 | 方向、单位、模式、回零参数、软限位、电子齿轮比 | 判断是“配置错”还是“硬件坏” |
| 通讯状态 | 控制卡在线状态、EtherCAT 主从站状态、PDO 映射 | 判断链路是否真正打通 |
| 日志 | 命令时序、位置反馈、状态切换、报警触发前后文 | 用于复盘偶发问题和状态机问题 |

推荐顺序：

1. 先确认供电、安全链和急停
2. 再确认 I/O 和报警码
3. 再检查参数、方向、单位和模式
4. 最后再回看应用层流程和线程逻辑

## 5. EtherCAT 专项排障顺序

如果你的项目采用 EtherCAT，推荐按这个顺序排：

1. 物理层：网线、屏蔽、供电、接地
2. 拓扑层：从站顺序、站号、模块识别
3. 协议层：ESI、PDO、SDO、同步模式
4. 驱动层：CiA 402、模式、控制字、状态字
5. 应用层：回零、限位、业务联锁、节拍逻辑

按层排查，效率比“看到不动就乱改参数”高得多。

## 6. 现场日志最少应该看什么

每次故障至少保留以下信息：

- 故障发生时间
- 当前工站状态
- 当前轴名
- 当前运动命令
- 指令位置与实际位置
- 报警码
- 急停/限位/门禁状态
- EtherCAT 主站和从站状态

如果这些数据没有记录，很多偶发问题都会变成“只能猜”。

## 7. 调试时的 10 条经验

1. 新设备第一次上电，速度和加速度一律保守。
2. 点动方向没确认前，不要直接做长距离绝对定位。
3. 回零前先确认限位和原点输入真的会变化。
4. 所有软限位都要有明确单位，不要混用 pulse 和 mm。
5. 任何自动流程前都先给出手动模式验证路径。
6. 急停恢复流程必须写成固定 SOP。
7. 每改一次驱动器关键参数，都要留记录。
8. 机械问题和电气问题经常会互相伪装，不要只盯软件。
9. 能做硬件联锁的，不要只做软件联锁。
10. 每解决一个现场问题，都应回写到本章形成团队知识库。

补一条和限位回零强相关的经验：

- 回零前先确认“当前方向离哪个硬限位更近”，不要在未知坐标下直接高速回零。

## 8. 验收前检查表

在设备准备交付前，至少确认：

- 回零 50 次以上无异常
- 单轴定位与重复定位满足工艺要求
- 急停、限位、门禁、气压联锁都有效
- 正极限、负极限触发后都只能朝安全方向释放
- 断电重启后的恢复流程明确
- 日志能定位到真实故障点
- 自动节拍在目标速度下连续运行稳定

## 9. 结论

调试不是“会动了就结束”，而是：

- 能动
- 稳定
- 可恢复
- 可定位
- 可交付

真正成熟的 PCBase 项目，现场工程师和软件工程师应该共用同一份排障语言。

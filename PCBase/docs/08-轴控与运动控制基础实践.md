## 1. 先把“轴”理解对

### 1.1 什么是轴 `Axis`

在运动控制里，轴不是单指“电机”。

更准确地说：

`轴 = 一个可独立控制、可被命令、可被反馈、可被保护的位置自由度`

例如：

- 丝杆模组的 X 方向移动，是一个轴
- 升降平台的 Z 方向移动，是一个轴
- 旋转工作台的转角，是一个轴
- 双驱龙门虽然可能有两台电机，但业务上也可能被抽象成一个“龙门轴组”

所以工程里常说的 `AxisX`、`AxisY`、`AxisZ`，本质上是在描述“控制对象”，不只是硬件器件名称。

### 1.2 轴与电机、驱动器、编码器、控制卡/主站的关系

可以把它们理解成一条控制链：

`上位机/控制程序 -> 控制卡或 EtherCAT 主站 -> 驱动器 -> 电机 -> 机械机构`

同时还有一条反馈链：

`编码器/光栅尺 -> 驱动器或控制卡 -> 上位机状态`

各自职责可以这样记：

| 对象 | 主要作用 | 工程上最常见的问题 |
| --- | --- | --- |
| 轴 `Axis` | 软件里的逻辑控制对象 | 抽象不清，业务代码直接绑死 SDK |
| 控制卡 / 主站 | 下发运动命令、规划轨迹、管理同步 | 卡在线但模式不对、PDO/参数不对 |
| 驱动器 | 把控制命令变成对电机的功率输出 | 使能没通、报警未清、模式没切对 |
| 电机 | 真正产生转动或直线运动 | 惯量不匹配、方向反、抱闸问题 |
| 编码器 / 光栅尺 | 提供实际位置和速度反馈 | 方向反、计数异常、分辨率没配对 |
| 机械机构 | 把电机运动变成工艺动作 | 背隙、卡滞、干涉、刚性不足 |

一个很实用的判断方法是：

- 电机是“执行器”
- 驱动器是“功率放大 + 伺服控制器”
- 编码器是“眼睛”
- 控制卡/主站是“运动大脑”
- 轴是你在软件里管理它们时使用的“统一对象”

### 1.3 单轴、双轴、多轴控制有什么区别

#### 单轴控制

只控制一个自由度，例如：

- Z 轴升降
- 滑台前后运动
- 转台旋转

单轴阶段最该搞懂的是：

- 使能
- 点动
- 停止
- 回零
- 绝对/相对定位
- 限位和报警

#### 双轴控制

典型场景：

- XY 平台
- XZ 取放机构
- 双轴对位机构

双轴比单轴多出来的，不只是“多一台电机”，而是：

- 坐标关系
- 同步起停
- 速度协调
- 插补轨迹
- 联锁条件

#### 多轴控制

典型场景：

- XYZ + R 平台
- 多工位搬运设备
- 龙门 + 输送 + 工艺头组合设备

多轴控制难点通常不在“让轴动起来”，而在：

- 多轴节拍协调
- 状态机管理
- 故障恢复
- 安全联锁
- 参数管理

工程上可以把它理解成一个递进关系：

`单轴 = 把一根轴控稳`

`双轴 = 把两个坐标关系控顺`

`多轴 = 把整机动作和异常恢复控住`

## 2. 三种最常见控制模式

### 2.1 位置控制

目标是“去哪里”。

常见命令：

- 绝对定位
- 相对定位
- 回零
- 插补

常见场景：

- 点位搬运
- 平台定位
- 点胶、锁附、拍照、加工位置切换

对上位机开发者来说，位置控制是最常见、最容易上手的模式。

### 2.2 速度控制

目标是“以多快的速度持续运动”。

常见命令：

- 点动 `Jog`
- 连续速度运动
- 搜索某个传感器
- 输送跟线运行

常见场景：

- 手动调机
- 输送轴连续运行
- 找边、找料、找传感器

速度模式的特点是：通常没有明确终点，要靠停止条件收住。

### 2.3 扭矩控制

目标是“输出多大力”或“维持多大张力/压力”。

常见场景：

- 收放卷张力控制
- 压合、拧紧、接触检测
- 某些浮动压紧机构

对多数 3C 自动化上位机项目来说，扭矩模式不是入门必修，但至少要知道：

- 它关注的是“力”而不是“位置”
- 用错场景会让设备行为非常难预测

如果你还处在样机开发阶段，优先把位置模式和速度模式吃透。

## 3. 现场最常见的轴状态词，到底是什么意思

| 术语 | 简明理解 | 工程提示 |
| --- | --- | --- |
| 使能 / Servo ON | 允许驱动器给电机输出扭矩 | 没使能，软件下发运动也不会真正执行 |
| 伺服上电 | 驱动器功率部分具备工作条件 | 不同品牌显示方式不同，不要只看 HMI |
| 报警 `ALM` | 驱动器或轴进入故障状态 | 先看报警码，不要只会反复点复位 |
| 复位 / Alarm Reset | 清故障位、恢复到可重新使能状态 | 能否成功复位取决于根因是否消失 |
| 急停 `EMG` | 紧急停止链路动作 | 这是安全动作，不是普通 Stop |
| 到位 `INP` | 实际位置进入允许误差范围 | 到位不等于完全稳定可加工 |
| 原点有效 | 原点开关或零点参考被检测到 | 回零逻辑一定要结合这个信号 |
| 正负限位 | 到达正向/负向运动边界 | 触发后应只允许安全方向退出 |

最容易混淆的 3 件事：

1. `报警复位` 不等于 `重新使能`
2. `到位` 不等于 `没有振动`
3. `软件停止` 不等于 `安全急停`

## 4. 运动控制基础动作

### 4.1 点动、定位、回零、停止、暂停、继续

#### 点动 `Jog`

按住就动，松开就停。  
最适合做：

- 初次确认方向
- 低速找位置
- 维护调机

#### 定位 `Move`

让轴到某个目标位置。最常见的就是：

- 绝对定位
- 相对定位

#### 回零 `Home`

建立可信坐标参考。  
如果是增量编码器系统，通常不开机回零就不能相信当前位置。

#### 停止 `Stop`

至少应分清两类：

- 减速停止：按设定减速度停下
- 急停或立即停：更快打断当前运动

#### 暂停 `Pause`

常见于多段轨迹、自动流程或输送协同场景。  
暂停不是简单“断使能”，而是要让控制系统知道当前流程停在什么状态。

#### 继续 `Resume`

继续执行暂停前的流程或轨迹。  
是否允许继续，通常要检查：

- 轴是否还在可恢复状态
- 前置联锁是否恢复
- 当前位置是否仍然安全

### 4.2 软限位与硬限位

#### 硬限位

真实的传感器或开关保护。  
作用是防止机构越界撞机。

#### 软限位

软件根据坐标定义的安全范围。  
作用是尽量在正常运行阶段就拦住危险命令。

推荐原则：

- 软限位在内
- 硬限位在外

也就是先让软件拦命令，再让硬件兜底。

### 4.3 绝对位置与相对位置

#### 绝对位置

目标值基于统一坐标系，例如：

- 去 `X=100.0 mm`
- 去 `Z=25.0 mm`

适合：

- 配方工位
- 固定拍照点
- 固定取放点

#### 相对位置

目标值基于当前位置，例如：

- 再前进 `5 mm`
- 再后退 `2 deg`

适合：

- 微调
- 补偿
- 步进式工艺动作

一个很实用的习惯是：

- 工艺点位优先用绝对位置
- 人工补偿和调试优先用相对位置

## 5. 高一点点，但非常常见的运动概念

### 5.1 插补

插补可以简单理解为：

`多轴按同一条时间规划一起动，最终走出你要的轨迹`

例如：

- X、Y 同时动，走一条直线
- X、Y 同时动，走一个圆弧

如果没有插补，两个轴虽然都动了，但轨迹不一定对。

### 5.2 电子齿轮

电子齿轮就是让从轴按比例跟随主轴。

比如主轴走 `100 mm`，从轴按比例走 `50 mm`。  
它本质上是在软件或驱动层定义一个“跟随比例关系”。

常见场景：

- 输送与取料同步
- 收放卷
- 多工位节距跟随

### 5.3 电子凸轮

电子凸轮比电子齿轮更进一步。  
它不是简单按固定比例跟，而是“主轴走到不同位置时，从轴按一条预定义曲线动作”。

常见场景：

- 包装
- 贴装
- 往复压合
- 需要按工艺节拍做周期动作的机构

### 5.4 跟随运动

跟随运动的重点是：

`一个轴的运动依赖另一个轴或外部参考的实时变化`

它可能是：

- 固定比例跟随
- 带偏移量的跟随
- 带补偿的跟随

### 5.5 同步运动

同步运动比“同时启动”要求更高。  
它强调的是：

- 时间同步
- 位置同步
- 速度同步

在 EtherCAT 项目里，多轴同步效果通常和以下因素强相关：

- 周期时间
- 抖动 `jitter`
- 分布式时钟
- 轴间参数一致性

## 6. 常见运动曲线和参数到底在控制什么

### 6.1 梯形曲线

最常见，也最容易理解：

1. 加速
2. 匀速
3. 减速

优点：

- 配置简单
- 大多数项目都能用

缺点：

- 冲击相对更明显
- 对高速、轻载、高精机构不一定够柔和

### 6.2 S 曲线

S 曲线可以理解为“更柔和地进入加速和减速”。  
它比梯形曲线更能减少机械冲击和振动。

适合：

- 高速搬运
- 机构刚性一般、容易抖的轴
- 对平滑性要求更高的工艺

### 6.3 加速度、减速度、加加速度的意义

| 参数 | 通俗理解 | 调太大容易怎样 |
| --- | --- | --- |
| 速度 | 跑多快 | 来不及稳定、超出机构能力 |
| 加速度 | 起步有多猛 | 冲击大、抖动、跟随误差增大 |
| 减速度 | 停车有多猛 | 刹车冲击大、易报警 |
| Jerk / 加加速度 | 加速度变化有多突兀 | 机构发颤、声音难听、轨迹不顺 |

一个工程经验：

`很多“轴不稳”不是速度太快，而是加减速太猛。`

## 7. 脉冲型控制卡与总线型控制，差在哪里

### 7.1 脉冲型控制

特点是控制卡给驱动器发：

- 脉冲
- 方向

优点：

- 结构直观
- 上手快
- 适合单机小轴数设备

缺点：

- 接线多
- 诊断信息少
- 多轴高级同步能力通常弱于总线型方案

### 7.2 EtherCAT / 总线型控制

特点是主站通过总线周期性和驱动器交换数据。  
在很多项目里，轴命令、状态字、位置反馈、I/O 状态都会走总线。

优点：

- 多轴同步强
- 远程 I/O 和驱动器统一管理方便
- 诊断信息更完整

缺点：

- 调试门槛更高
- 需要理解主站、PDO、模式、状态机

### 7.3 和 CiA 402 的关系

CiA 402 可以粗略理解成：

`一种让很多伺服驱动器用相似方式被上位控制的通用模型`

它最直接影响你的，通常是：

- 驱动器怎么使能
- 怎么复位
- 当前是什么运行模式
- 状态字怎么看

所以在 EtherCAT 项目里，“轴在线但不动”很多时候不是总线坏了，而是：

- 运行模式不对
- 控制字顺序不对
- 报警或互锁没解除

## 8. 现场调试时，先看哪几类证据

不要一看到轴不动，就立刻改参数。  
真正高效的排障，通常是按“证据链”来判断。

| 证据 | 你要看什么 | 典型用途 |
| --- | --- | --- |
| 电气图 | 限位、原点、急停、使能、报警回路怎么接 | 判断信号方向、联锁路径、是否少线断线 |
| I/O 状态 | 输入点是否随现场动作真实变化 | 判断开关、传感器、接线和极性 |
| 驱动器报警码 | 面板报码、软件报码、手册说明 | 找到故障根因入口 |
| 参数配置 | 方向、单位、模式、限位、回零参数 | 判断“配置错”而非“硬件坏” |
| 通讯状态 | 卡是否在线、总线是否 OP、PDO 是否正常 | 判断链路是否真正打通 |
| 日志 | 命令时序、状态变化、位置和报警记录 | 复盘偶发问题和流程时序问题 |

一个推荐排查顺序：

1. 先确认安全链和供电
2. 再看 I/O 和报警码
3. 再看模式、参数、单位
4. 最后才去怀疑复杂的软件逻辑

## 9. 上机前确认项

如果你要把一套轴控系统第一次真正上机，建议至少确认以下内容：

- 电源、急停、STO、安全继电器状态正常
- 电机方向和软件正方向定义一致
- 正负限位输入逻辑已确认
- 原点开关位置和触发逻辑已确认
- 单位换算已明确：`pulse/mm/deg/count`
- 最大速度、加速度、减速度先保守配置
- 报警复位、使能、停止、回零 SOP 已确定
- HMI 显示状态和驱动器真实状态能对得上
- 日志里能看到命令、位置、报警、I/O 关键信息

如果以上还没确认，就不要急着跑自动流程。

## 10. 常见问题，怎么想更容易定位

### 10.1 轴不动

先问自己 5 个问题：

1. 真的使能了吗
2. 急停、STO、门禁有没有挡住
3. 驱动器还在报警吗
4. 当前模式对吗
5. 命令发出去了，还是被联锁拦住了

### 10.2 轴抖动、异响、啸叫

常见不是“程序有 bug”，而是：

- 增益不合适
- 加速度太猛
- 机械刚性不足
- 编码器方向或电机相序有问题

建议先低速、低加速度验证，再逐步提参数。

### 10.3 丢步或跟随误差大

脉冲轴常见看法是“丢步”，伺服轴常见表现是“跟随误差大”。  
它们在现场表现都可能是：

- 位置越来越偏
- 重复定位越来越差
- 一加速就报错

优先检查：

- 单位换算对不对
- 机械是否卡滞
- 速度和加速度是否超能力
- 编码器反馈是否稳定

### 10.4 回零失败

先分清到底是哪种失败：

- 根本没开始动
- 动了但方向错
- 找到 ORG 但停不准
- 找到原点后状态没更新成已回零

不同失败类型，对应问题层级完全不同。

### 10.5 报警清不掉

很多人会一直点 `Reset`，但报警清不掉通常说明：

- 根因还在
- 安全链没恢复
- 驱动器要求特定复位时序
- 软件只清了页面状态，没有真正清驱动器故障

这时一定要同时看：

- 驱动器面板报码
- 报警码手册
- I/O 状态
- 软件日志

## 11. 开发实践建议：怎么把代码写得更稳

### 11.1 先设计统一轴抽象层

建议至少统一以下能力：

- 读状态
- 使能/去使能
- 报警复位
- 回零
- 点动
- 绝对/相对定位
- 停止

这样做的价值是：

- 换控制卡时，上层流程不用重写
- 更容易做模拟器和离线联调
- 更容易把轴对象纳入统一状态机

### 11.2 运动命令不要直接耦合业务按钮

更推荐的结构是：

- 业务状态机决定“现在该做什么”
- 运动层负责“怎么安全地执行这个动作”

不要在按钮事件里直接写一堆：

- `MoveAbs`
- `Sleep`
- `if`
- `再 Move`

这样一到现场异常恢复时，逻辑会非常难收拾。

### 11.3 配置、参数表、日志一定要独立出来

至少要独立管理这些数据：

- 轴名
- 工程单位
- 脉冲当量 / 编码器分辨率
- 软限位
- 回零参数
- 默认运动参数
- 报警码表

日志至少记录：

- 时间
- 轴名
- 命令类型
- 目标位置
- 实际位置
- 报警码
- I/O 条件

### 11.4 单位换算要从第一天说清楚

现场最容易乱的就是单位。

常见几种：

- 脉冲 `pulse`
- 毫米 `mm`
- 角度 `deg`
- 编码器计数 `count`

建议工程里统一原则：

- UI 和业务层尽量用工程单位，如 `mm`、`deg`
- 驱动或控制卡需要的底层单位，在适配层换算

这样才能避免：

- HMI 显示是 `mm`
- SDK 下发的是 `pulse`
- 日志记的是 `count`

最后没人知道谁对谁错。

## 12. 四个最实用的概念示例

### 12.1 单轴点动与定位

推荐最小流程：

1. 清报警
2. 使能
3. 低速点动确认方向
4. 停止
5. 回零
6. 小距离绝对定位
7. 再做相对定位

如果第 3 步方向都没确认，不要直接跑长距离绝对定位。

### 12.2 回零流程示例

一个常见且实用的流程可以理解为：

`检查前置条件 -> 清报警 -> 使能 -> 粗找原点 -> 精找边沿/Index -> 加 Offset -> 写入 Homed 状态`

这里最关键的不是“语法”，而是以下 3 件事都要成立：

- 现场信号真的对
- 驱动模式真的对
- 应用状态真的更新

### 12.3 双轴联动概念示例

例如一个 XY 平台从左下角移动到右上角：

- 如果你分别先走 X 再走 Y，那只是顺序动作
- 如果 X、Y 按同一轨迹规划一起走，那才更接近联动或插补

所以“双轴联动”的核心不是轴数，而是“坐标关系和同步规划”。

### 12.4 常见控制流程状态机

一个够用的上位机状态机，通常至少可以分成：

```text
PowerOn
  -> Initializing
  -> SafetyChecked
  -> ServoReady
  -> Homed
  -> Ready
  -> Manual / Auto
  -> Paused
  -> Fault
```

只要状态机清楚，很多“到底该不该允许运动”的问题就容易判断。

## 13. 给初学者和上位机开发者的最后建议

如果你准备开始做第一台设备，请优先把这几件事做扎实：

1. 单轴的使能、回零、点动、定位、停止跑通
2. 限位、原点、急停、报警复位全部看懂
3. 单位换算不要混乱
4. 日志和状态机从第一版就建立起来
5. 双轴和多轴功能一定建立在单轴稳定基础上

记住一句非常工程化的话：

`运动控制最怕的不是“不动”，而是“看起来能动，但为什么动、为什么停、出了错怎么恢复，全说不清”。`

# CIM Demo 调试工具清单

本文档用于补充 [`README.md`](README.md) 中的启动说明，帮助你在本地更高效地观察 `接口 -> 模拟器 -> 数据库` 的运行结果。

## 推荐工具

| 工具 | 用途 | 备注 |
| --- | --- | --- |
| Swagger UI | 直接调试 REST API | `http://localhost:5100/swagger` |
| `curl` | 命令行调用接口 | 适合脚本化演示 |
| `jq` | 美化 JSON 输出 | 搭配 `curl` 使用 |
| `nc` / `telnet` | 连接模拟器 TCP 控制端口 | 默认 `127.0.0.1:7001` |
| `sqlite3` | 直接查看 SQLite 数据库 | 推荐配合绝对路径数据库 |
| VS Code / Rider / Visual Studio | 阅读源码与断点调试 | 适合二次开发 |

## 最常用的 4 类调试动作

### 1. 看接口

```bash
curl -s http://localhost:5100/api/equipment/SMT-01/status | jq
```

### 2. 看模拟器

```bash
nc 127.0.0.1 7001
STATUS
STATE SMT-01 RUNNING
TEST TEST-01
```

### 3. 看数据库

假设数据库路径统一设置为 `/tmp/cim-demo/cim.db`：

```bash
sqlite3 /tmp/cim-demo/cim.db ".tables"
sqlite3 /tmp/cim-demo/cim.db "select EquipmentId, State, UpdatedAt from EquipmentStatus;"
sqlite3 /tmp/cim-demo/cim.db "select SerialNumber, EventType, EquipmentId, EventTime from TrackEvents order by Id desc limit 20;"
sqlite3 /tmp/cim-demo/cim.db "select SerialNumber, StationId, Verdict, TestedAt from TestResults order by Id desc limit 20;"
```

### 4. 看日志

- `Cim.RestApi`：看接口请求是否成功、是否返回 400 / 404 / 500
- `Cim.DeviceSimulator`：看设备周期输出、状态变化、告警与测试结果事件
- `Cim.MqWorker`：看订阅是否建立、事件是否被处理（更适合未来替换真实消息总线时观察）

## 推荐启动姿势

为了避免不同进程把 `./data/cim.db` 写到不同目录，建议统一指定绝对路径。

**macOS / Linux**

以下命令默认从当前目录 `CodeDemo/CIM/` 执行。

```bash
mkdir -p /tmp/cim-demo
Database__Path=/tmp/cim-demo/cim.db dotnet run
```

```bash
# terminal 1
cd src/Cim.RestApi
Database__Path=/tmp/cim-demo/cim.db dotnet run

# terminal 2
cd src/Cim.DeviceSimulator
Database__Path=/tmp/cim-demo/cim.db dotnet run

# terminal 3（可选）
cd src/Cim.MqWorker
Database__Path=/tmp/cim-demo/cim.db dotnet run
```

**Windows PowerShell**

以下命令默认从当前目录 `CodeDemo/CIM/` 执行。

```powershell
New-Item -ItemType Directory -Force -Path "$env:TEMP\cim-demo" | Out-Null
```

```powershell
# terminal 1
cd src/Cim.RestApi
$env:Database__Path = "$env:TEMP\cim-demo\cim.db"
dotnet run

# terminal 2
cd src/Cim.DeviceSimulator
$env:Database__Path = "$env:TEMP\cim-demo\cim.db"
dotnet run

# terminal 3（可选）
cd src/Cim.MqWorker
$env:Database__Path = "$env:TEMP\cim-demo\cim.db"
dotnet run
```

## 常见观察点

```bash
sqlite3 /tmp/cim-demo/cim.db "select EquipmentId, EquipmentName, State, RecipeId, LotId, UpdatedAt from EquipmentStatus;"
```

```bash
sqlite3 /tmp/cim-demo/cim.db "select SerialNumber, LotId, EquipmentId, StationId, EventType, EventTime from TrackEvents order by Id desc;"
```

```bash

```

### 告警有没有闭环？

```bash

```

## FAQ

### 为什么 `MqWorker` 启动了却看起来没有收到 `DeviceSimulator` 的消息？

因为当前事件总线是 `InMemoryEventBus`，只能在同一进程内共享。`MqWorker` 的意义更多是保留一个未来接 RabbitMQ / Kafka 的消费层结构。

### 为什么有时查不到刚才写入的数据？

优先确认三件事：

1. 你是否把 `Database__Path` 配成了同一个绝对路径
2. 你查的是不是同一份数据库文件
3. 你执行的是 API 写入、还是模拟器事件写入

### 本地演示时最推荐的最小组合是什么？

`RestApi + DeviceSimulator + sqlite3/curl/nc`。

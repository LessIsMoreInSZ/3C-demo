# C# 仪器通信常见问题与排查

## 1. 设备连上了，但读不到响应

优先检查：

- 端口号是否正确
- 波特率/校验位/停止位是否匹配
- TCP 端口是否写对
- 是否漏了 `\n` 或 `\r\n`
- 是否命令太长、设备还没处理完

---

## 2. 串口一直超时

常见原因：

- 打错 COM 口
- 串口参数不一致
- 设备实际是 RS-485，但按 RS-232 用了
- 设备需要先握手或先发送唤醒命令

---

## 3. LAN 通信失败

排查步骤：

1. `ping` 设备 IP
2. 确认端口可访问
3. 确认仪器支持该协议（Raw Socket / VXI-11 / HiSLIP）
4. 检查防火墙
5. 检查是否需要先建立会话

---

## 4. VISA 打不开资源

可能原因：

- VISA 运行时未安装
- 资源字符串写错
- 仪器驱动未安装
- 设备未枚举成功

资源字符串示例：

- `GPIB0::22::INSTR`
- `ASRL3::INSTR`
- `TCPIP0::192.168.1.100::inst0::INSTR`
- `USB0::0x1234::0x5678::INSTR`

---

## 5. USB 设备识别了但不能通信

常见原因：

- 设备是 HID，但按串口或 TCP 在访问
- 设备是 USB-TMC，但没走 VISA
- 设备需要专用驱动或厂商 SDK
- 系统权限或驱动签名问题

---

## 6. 建议的代码习惯

- 所有命令都记录日志
- 为每次请求设置超时
- 建立统一异常类型
- 关闭连接时尽量释放资源
- 对仪器做状态复位和初始化

---

## 7. 最后建议

如果你不确定设备属于哪种通信方式，先查：

1. 仪器说明书
2. 接口标签
3. 厂商驱动包
4. VISA 资源枚举结果

这样通常能最快定位问题。
